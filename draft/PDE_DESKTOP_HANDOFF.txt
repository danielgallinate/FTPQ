1. RESUMEN DEL PRODUCTO
--------------------------------------------------------------------------------
Aplicacion de escritorio portable (Windows nativo + macOS), ejecutable, con
interfaz GRAFICA (no terminal/TUI). Objetivo: conectar a SFTP, gestionar llaves
SSH, explorar archivos remotos, previsualizar y descargar, y analizar contenido
CSV con pandas usando reglas definidas localmente (perfiles JSON).

NO es una copia del PDE SFTP Validator completo. No consulta base de datos ni
Snowflake en esta fase. La validacion "oficial" contra logs de extract_history
queda FUERA de alcance hasta una fase futura.


2. FUNCIONALIDADES PEDIDAS / ENTENDIDAS
--------------------------------------------------------------------------------

2.1 SFTP — NUCLEO OBLIGATORIO
  [F01] Conector SFTP (autenticacion por llave privada SSH)
  [F02] Configurar servidor: host, puerto, usuario
  [F03] Elegir que llave privada usar para la conexion (selector en UI)
  [F04] Configurar ubicacion/carpeta donde buscar llaves (default ~/.ssh;

  [F05] Probar conexion SFTP (test auth) antes o durante el uso
  [F06] Mostrar contenido del SFTP en pantalla: carpetas y archivos del

  [F07] Navegar carpetas (entrar, subir, refrescar)
  [F08] Abrir / previsualizar archivo en pantalla (texto y CSV; ver limites
        en seccion 4)
  [F09] Descargar archivo y elegir carpeta de destino local (file picker OS)

2.2 PANDAS — ANALISIS DE ARCHIVOS (SIN BASE DE DATOS)
  [F11] Analizar un archivo CSV seleccionado (desde SFTP descargado a temp,
        o archivo local ya descargado)
  [F12] Estadisticas basicas: filas, columnas, tipos, valores nulos
  [F13] Duplicados y valores unicos (por columna o por combinacion de columnas)
  [F14] Deteccion de columnas candidatas a "clave" (cardinalidad, unicidad)
  [F15] Validar contenido del archivo contra reglas de un PERFIL LOCAL (JSON):
        - delimitador esperado (tab, comma, pipe, etc.)
        - columnas requeridas / opcionales
        - metadatos de negocio definidos en perfil (ej. nombre clinica,
          datasource, config name) comparados contra columnas o valores del CSV
        NOTA: estas reglas NO vienen de Postgres; el usuario o QA las define
        en el perfil JSON del proyecto
  [F16] Validar todos los archivos de una carpeta remota o local (cola
        secuencial; un archivo a la vez; resultados en tabla/lista en UI)

4. RESTRICCIONES Y LIMITES FUNCIONALES ACORDADOS
--------------------------------------------------------------------------------
  - Preview en pantalla: solo texto y CSV; limite de tamano en RAM
    (recomendado: primeros 512 KB o 500 lineas; configurable en perfil)
  - Archivos binarios (PDF, zip, etc.): solo descargar; no preview inline
  - Analisis pandas: limite de MB por archivo (recomendado aviso si > 50 MB)
  - Validacion en lote: secuencial; no cargar todos los CSV en memoria
  - Archivos temporales en disco (downloads/, tmp/analysis/); limpiar por sesion
  - Test SFTP siempre real contra AWS Transfer; no confiar en flags "verified"
    de sistemas externos (leccion aprendida en config3 vs config10)
  - Rutas siempre con pathlib.Path / expanduser; sin concatenar con "/"
  - Reinicio de app en Windows: subprocess, no os.execv a secas
  - VPN corporativa requerida para SFTP en entornos PDE


5. ARQUITECTURA DE PROCESO Y MEMORIA (OBJETIVO)
--------------------------------------------------------------------------------
  - Un proceso principal (app de escritorio)
  - UI en hilo principal; operaciones de red (SFTP) y pandas en worker threads
  - Una sesion SFTP activa; cerrar al cambiar perfil o llave
  - pandas: import lazy (solo al abrir pestana Analisis) para ahorrar RAM al inicio
  - RAM estimada:
      Solo SFTP activo     ~ 130-200 MB
      SFTP + pandas        ~ 180-350 MB (depende tamano CSV)
  - Ejecutable empaquetado estimado:
      SFTP + UI + pandas   ~ 120-200 MB (one-folder)

8. ALTERNATIVAS (NOTA — NO DECIDIR AUN EN ESTE DOCUMENTO)
--------------------------------------------------------------------------------

  UI
    | Opcion        | Pros                          | Contras                    |
    |---------------|-------------------------------|----------------------------|
    | Flet          | Rapido, Python puro, portable | Tablas muy grandes mas flojas|

    | Electron      | Ecosistema enorme             | Muy pesado (~150MB+)       |

  Empaquetado
    | Opcion        | Pros                          | Contras                    |
    |---------------|-------------------------------|----------------------------|
    | PyInstaller   | Funciona bien con paramiko    | Antivirus a veces alerta   |
    | flet build    | Integrado si UI=Flet          | Menos control fino         |
    | briefcase     | Estilo app store              | Windows mas complejo       |

  Config / perfiles
    | Opcion        | Pros                          | Contras                    |
    |---------------|-------------------------------|----------------------------|
    | JSON files    | Simple, versionable, mocks    | Sin UI de edicion avanzada |
    | .env + JSON   | Compatible con habitos PDE    | Dos fuentes de verdad      |
    | Solo .env     | Familiar para QA              | Menos estructura reglas    |

  Analisis CSV
    | Opcion        | Pros                          | Contras                    |
    |---------------|-------------------------------|----------------------------|
    | pandas        | Ya usado en validator PDE     | RAM en archivos grandes    |
    | polars        | Mas rapido, menos RAM         | Cambio de stack            |
    | pyarrow       | Streaming parcial             | Mas bajo nivel             |
